# BingX / MEXC 시장 데이터 중계

GitHub Pages에서 BingX와 MEXC를 직접 요청하면 브라우저의 출처 정책 또는 거래소 접근 제한 때문에 공식 응답을 읽지 못할 수 있다. `relay-config.js`에 지정된 서버가 두 거래소의 공개 시장 데이터만 조회한다. 나머지 거래소는 기존 경로를 사용한다.

- 현재값: BingX premiumIndex, MEXC funding_rate
- 정산 이력: BingX fundingRate, MEXC funding_rate/history
- 캔들: BingX swap v3 klines, MEXC contract kline
- 전체 종목 목록: BingX contracts, MEXC contract/detail
- 전체 24시간 시세: BingX ticker, MEXC contract/ticker
- 정산 주기: 현재값 응답의 fundingIntervalHours / collectCycle

`market-relay.mjs`는 Sites 서버의 동일 파일을 보관한 사본이다. 서버 소스를 수정할 때는 두 저장소의 파일을 함께 갱신한다. 서버는 `GET /api/market`의 exchange/path와 허용된 매개변수만 받아 공식 URL을 구성한다. 브라우저의 Origin, 쿠키, 인증 정보는 거래소로 전달하지 않는다. 임의 URL, 개인 계정, 주문 API는 지원하지 않는다.

성공한 현재값은 최대 3초, 캔들과 이력은 최대 10초 보관한다. 요청 간에는 완료된 JSON 문자열과 예약 시각만 보관하며, 실행 중인 fetch나 Promise는 공유하지 않는다. 취소된 요청이 다음 요청을 막지 않도록 각 호출의 취소 신호와 응답 제한을 독립적으로 적용한다. 실패한 응답은 이전 성공값으로 대체하지 않는다. `X-Market-Fetched-At`을 차트에 전달해 실제 조회 시각을 표시한다. BingX 요청은 숫자 시각으로 순서를 예약해 간격을 두고 timestamp를 생성하며, 네트워크 실패일 때만 공식 보조 주소를 이용한다.

BingX 정산 이력은 endTime만 전달할 때 성공 코드와 null 데이터가 반환되는 것을 확인했다. 90일의 startTime/endTime 구간을 함께 전달해 정산 기록을 조회하고, 가장 오래된 기록의 직전 시각으로 구간을 옮겨 과거 이력을 계속 수집한다. 성공 코드의 null 이력은 빈 정산 기록으로 처리한다.

차트 타임프레임은 1m / 3m / 5m / 15m / 30m / 1h / 2h / 4h / 1d / 1w / 1M이다. 주봉은 월요일 00:00 UTC, 월봉은 달력의 월 경계를 사용한다. 6개 거래소의 원본 주봉·월봉을 조회하고, 월봉을 30일봉으로 합성하지 않는다. MEXC의 3m는 Min1, 2h는 Min60의 실제 OHLCV를 UTC 경계에 맞춰 합성한다. Bitget의 과거 2h도 1H를 합성한다. 원본 봉이 누락된 과거 합성 봉은 만들지 않으며, 페이지 경계의 불완전한 봉은 다음 페이지에서 다시 조회한다.

로컬 개발은 localhost, 127.0.0.1, [::1]의 HTTP/HTTPS 출처를 허용하며 허용된 출처만 정확하게 CORS 응답에 반영한다. 임의 외부 출처와 localhost를 흉내 낸 도메인은 허용하지 않는다.

Bitget 최신 캔들 요청에는 endTime을 넣지 않아 진행 중인 봉을 포함한다. 과거 페이지는 API가 endTime을 봉 경계로 내림하는 규칙을 고려해 커서를 올림한 뒤 요청하므로 페이지 사이의 한 봉이 빠지지 않는다.

하단 날짜 이동 버튼 또는 Alt+G로 한국 시간(UTC+9)을 지정한다. 아직 수집하지 않은 구간은 날짜 주변 캔들을 직접 조회하며, 수집 완료 시 현재 화면의 날짜를 유지한다. 전체 캔들 수집에 3,000봉 같은 고정 상한은 없지만 상장 시점과 거래소 API의 실제 보관 범위를 넘을 수는 없다. 가격 캔들과 정산 기록의 제공 범위는 다를 수 있다. 기록 없는 날짜를 최신 날짜나 가짜 값으로 대체하지 않는다.

차트 좌우 이동 시 화면 가장자리와 아직 불러오지 않은 구간의 캔들을 요청한다. 전체 이력 수집 중에도 먼저 수집된 페이지를 사용할 수 있다. 과거 전체 수집을 중지해도 실시간 갱신과 이동 구간 조회는 계속된다. 날짜 이동은 선택한 봉을 중앙에 맞추며, 이력 추가 중에는 시각을 기준으로 화면을 유지한다.

실시간 캔들은 3초, 현재 펀딩비는 10초, 정산 이력은 60초마다 요청한다. 최신 봉은 `update`로 거래량·펀딩비 시간점·RSI·정산 주기와 함께 갱신하며, 뒤늦은 과거 페이지가 현재 봉을 덮어쓰지 않는다. RSI는 재귀 계산 상태를 이어 사용하며, 아직 수집하지 않은 시간 간격은 이어서 계산하지 않는다. 현재 미정산 구간의 주기는 공식 응답 또는 최근 정산 간격을 사용하며, 과거 기록이 없는 구간에는 현재 정책을 소급하지 않는다.

가격축의 현재가 아래에는 각 타임프레임 봉의 남은 시간이 표시되고 시간축 오른쪽에는 한국시간 시계가 표시된다. 이동 버튼은 차트 위에 마우스가 있거나 키보드로 버튼에 접근한 경우 표시된다. RSI 설정의 모습 탭에서 상단·중간·하단 기준선의 표시, 값, 색상, 두께, 선 모양을 각각 변경할 수 있다.

4분할 차트는 `chart-workspace.js`가 기존 차트와 3개의 독립 차트 문서를 구성한다. 1화면으로 돌아가면 추가 문서를 제거하고 시세 요청을 취소한다. 분할에서는 최근 캔들을 우선 조회하고 과거 구간은 이동 시 추가 조회한다. `market-shared.js`가 차트 간 같은 요청, 짧은 캐시, BingX 요청 간격을 공유한다. 한 차트의 취소는 다른 차트의 조회를 중단하지 않는다. 분할 캔들은 약 9초, 현재 펀딩비는 약 20초 간격으로 갱신해 BingX의 공유 요청 간격을 지킨다. 단일 화면의 캔들 3초·현재값 10초 갱신은 유지한다.

종목 이름을 누르면 `symbol-picker.js`가 6개 거래소의 거래 가능한 USDT 무기한 계약을 검색·즐겨찾기·현재가·24시간 등락·거래대금과 함께 표시한다. `market-catalog.js`는 Bybit의 모든 cursor 페이지를 조회한다. 목록에서는 화면에 보이는 행만 만들고, 열린 동안에만 시세를 갱신한다. 종목 정보는 최대 5분 캐시하며 갱신 실패 시 이전 목록임을 표시한다.

종목 선택창의 첫 검색 범위는 `모든 거래소`다. 개별 거래소 필터도 제공하며 같은 페이지 안에서 다시 열면 선택한 범위를 유지한다. 전체 조회는 거래소별 캐시·공유 요청을 그대로 사용하고, 받은 목록부터 표시한다. 검색어 입력은 받은 목록만 필터링하며 API를 다시 요청하지 않는다. 전체 결과에서도 동일한 코인을 거래소별로 구분하고, 행을 누르면 선택한 차트에 그 거래소·심볼을 함께 전달한다. 실패한 거래소와 이전 목록을 쓰는 거래소를 구분해 표시한다. 전체 범위에서 결과가 없을 때 임의의 거래소로 직접 이동하지 않으며, 수동 심볼 이동은 개별 거래소 범위에서만 제공한다.

각 분할의 상단 최대화 버튼이나 오른쪽 아래 확대 버튼은 해당 차트만 펼치며, 다시 누르거나 Alt+Enter / Esc로 4분할에 복귀한다. 선택한 차트에서 Alt+Enter도 같은 동작을 한다. 확대 중에도 나머지 차트 문서와 설정을 유지하고, 복귀할 때 새 조회나 문서 재생성을 하지 않는다. 상단의 별도 `작업 영역 전체화면` 버튼으로 브라우저 전체화면을 전환할 수 있으며, 그 안에서도 각 차트 최대화가 동작한다.


## 전체화면의 오른쪽 패널

`workspace-sidebar.js`가 기존 `chartGrid`와 백테스팅 dock을 `workspaceChartColumn`에 넣고, 실제 오른쪽 패널 DOM을 같은 `chartWorkspace` 안에 배치한다. 네이티브 전체화면과 CSS 대체 전체화면 모두 같은 작업 영역을 사용하므로 설정·현재 탭·선택 차트를 복제하거나 다시 만들지 않는다. 일반 화면과 전체화면에서 오른쪽 레일의 화살표로 접고 펴며, 전략·펀딩·소식·스캐너·순위 아이콘으로 해당 기존 탭을 바로 연다. 레일은 접은 상태에도 남는다. 접기 상태는 브라우저 설정에 저장하고 960px 미만에서는 처음에 접힌 상태로 시작한다. 좁은 화면에서 펼친 패널은 차트 위로 열어 차트 폭을 과도하게 줄이지 않는다. 신호 패널은 접힌 동안 DOM 목록을 다시 그리지 않고, 소식의 주기 조회도 쉬며 열 때 기존 최신 상태를 표시한다.

### 펀딩 데이터 표시 기준

차트 주기는 펀딩 정산 주기와 별개다. 현재 미정산율과 다음 정산 시각은 거래소의 공식 현재값 응답을 사용하며, 단일 화면 약 10초·4분할 약 20초 간격으로 재조회한다. 확정 정산 이력은 60초 간격으로 갱신한다. 화면이 숨겨지면 갱신을 쉬고 API 지연·오류·요청 제한이 생길 수 있으므로 즉시 반영이나 오차 0을 보장하지 않는다. 표시율은 소수점 6자리에서 반올림한다.

큰 봉에 여러 정산 기록이 포함되면 펀딩비 막대는 그 봉의 확정 정산율 중 최저값을 표시한다. 신호의 실제 정산 시각은 별도로 유지한다. 과거 정산 주기는 기록의 시간 간격으로 관측하며, 큰 봉에는 관측한 최소 간격을 사용한다. 최신 미정산 구간은 공식 현재 주기를 우선한다. 누락된 이력으로 실제 과거 정책을 완전히 복원할 수는 없다. 분봉부터 달력 주봉·월봉까지 동일 원본 기록을 해당 봉 경계에 연결한다. 지표 제목과 현재율에 설명 툴팁을 제공한다.

`funding-history.js`는 가격 페이지와 별도로 보이는 날짜 범위의 정산 이력을 모든 페이지에서 수집한다. Bybit 200건 등 첫 페이지가 화면의 일봉·주봉·월봉 전체를 덮는다고 가정하지 않는다. 앞뒤 24시간의 실제 정산도 받아 간격을 계산하고, 이미 완료한 범위는 재사용한다. 화면이나 종목이 바뀌면 이전 조회를 취소하고, 여러 페이지의 화면 반영은 250ms 간격으로 묶는다. 페이지 반복·API 오류는 완료로 표시하지 않으며 없는 과거 기록은 만들지 않는다. 큰 봉의 과거 최소 간격을 최신 공식 주기로 덮어쓰지 않는다.

과거 주기는 `FundingEngine.observedCycles`에서 같은 정산 간격이 연속 2회 이상 관측될 때만 표시한다. `1h, 1h, 2h, 4h, 4h`처럼 단발로 생긴 2h는 누락 또는 전환 경계를 구별할 수 없어 확인 불가로 남기며, 단발 2h 자체를 주기로 표시하지 않는다. 이후 연속 4h가 관측되면 앞의 연속 1h와 비교해 `관측 1h → 4h (경계 미확인)`를 첫 4h 정산 기록에 표시한다. 공백 구간을 채우거나 정확한 정책 변경 시각이라고 확정하지 않으며, 앞뒤 주기가 같으면 변경 마커를 만들지 않는다. 주기 증가·감소를 모두 표시하고, 일봉·주봉·월봉 등 한 봉에 여러 변화가 있으면 문구를 합쳐 앞의 변화를 덮어쓰지 않는다. 6개 거래소의 모든 코인과 1화면·4분할은 같은 공통 함수를 사용한다. 반복된 간격도 공식 과거 정책으로 확정하지 않으며 마커는 `관측 2h → 4h`처럼 표시한다. 공식 현재 API가 2h를 제공하면 그대로 지원한다. 상단 배지는 공식 현재값과 연속 기록에 근거한 추정을 구분하며, 현재 근거가 없을 때 오래된 과거 간격을 현재 공식값으로 사용하지 않는다. 원본 정산 시각과 펀딩율은 이 표시 판단으로 변경하지 않는다.

### 백테스팅 대상과 수집 상태

차트 따라가기는 실행 시점의 선택 차트에서 거래소·심볼·기준 주기를 함께 읽는다. 다른 분할의 종목을 로드하면 구독자도 즉시 갱신한다. 진행 중 대상이나 선택 분할이 바뀌면 기존 수집/worker를 취소하며, 수동 지정 모드는 차트와 독립적인 대상을 유지한다. 수집한 데이터의 거래소·심볼·기준 주기를 worker 실행 전에 검사한다.

1분봉 고정 RSI 추가 진입과 조건 탐색은 보조 1분봉 기록도 수집한다. 진행 문구에는 `기준 3분 / 보조 1분봉 RSI·체결 검증`처럼 구분해 표시한다. 실패하거나 다른 대상을 선택한 동안 남아 있는 결과에는 이전 종목·주기를 별도 표시한다. Bybit 10016 서버 오류는 최대 3회 지연 후 재시도하고, kline 요청은 같은 심볼·주기·커서를 유지하면서 페이지 크기만 줄인다. 계속 실패하면 명시적인 오류로 남기며 다른 종목의 기록이나 빈 성공 응답으로 대체하지 않는다.

설정의 코인 검색은 해당 거래소의 공식 거래 가능 목록을 캐시해서 사용한다. `bt`처럼 앞부분만 입력하면 BTC·BTW 등 일치하는 종목을 앞부분 일치 우선으로 최대 12개 표시하고 방향키/Enter로 선택한다.

## 분할 차트별 신호 패널

`signal-sidebar.js`는 오른쪽 전략/펀딩 신호 패널을 현재 선택한 차트에 연결한다. 선택 차트 번호·거래소·코인·주기를 표시하고, 각 문서의 독립적인 전략 ON/OFF·펀딩 기준·목록 필터·펀딩 목록 페이지를 사용한다. 공유 패널의 체크박스 DOM을 다른 차트의 전략 계산에 읽어 쓰지 않는다. 차트 전환은 기존 계산 결과만 표시하며 시세 재요청이나 전략 재계산을 하지 않는다. 설정 변경 시에는 대상 차트만 다시 계산하고 마커를 갱신한다. 설정은 열려 있는 차트 문서마다 유지되며, 새 문서를 여는 경우 기본 설정을 사용한다.

`chart-workspace.js`의 신호 구독은 선택한 하위 차트만 전송하게 한다. 80ms 동안 연속 갱신을 모으고 전략 목록은 최대 80건, 펀딩 목록은 100건씩 전송한다. 캔들 전체나 차트 엔진을 패널로 복사하지 않는다. 메시지는 같은 출처의 실제 차트 iframe/부모에서만 받으며 코인·거래소·주기·로드 세대가 일치할 때 반영한다. 코인 변경 중에는 이전 목록을 비우고, 오래된 목록의 클릭이나 늦은 응답이 새 코인을 덮어쓰지 못하게 한다. 신호의 이동 버튼은 선택한 차트의 실제 신호를 찾아 이동하며 다른 차트의 코인을 다시 로드하지 않는다.

## 공식 상장폐지 공지

`news-ui.js`가 거래소·시장·코인 검색, KST 게시 기간 선택, 30건씩 이전/다음 목록, `과거 공지 더 가져오기`를 제공한다. 뉴스는 가격 데이터 요청과 독립적이고 4분할 하위 문서에서는 실행하지 않는다. 검색 입력은 300ms 뒤에 요청하며 새 조건으로 바뀌면 이전 요청을 취소한다. 화면에는 현재 페이지의 최대 30건만 그린다.

`server/delisting-news.mjs`는 고정된 공식 출처에서 메타데이터를 읽고, `server/news-archive.mjs`는 같은 Sites 프로젝트의 `GET /api/news`와 D1 보관함을 구현한다. Binance·Bybit는 공식 공지 API의 페이지 매개변수, Bitget·MEXC·OKX는 공식 목록의 이전 페이지를 사용한다. BingX는 기존 공식 목록이 비어 있거나 변경되면 오류를 표시한다. 임의 URL·개인 정보·주문 요청은 받지 않는다. 요청 허용 조건은 `exchange`, `scope`, `q`, `start`, `end`, `cursor`, `limit`(최대 50), `mode`이다.

- `mode=latest`(기본): 선택 출처의 최신 첫 페이지를 확인하고 보관된 결과를 조회한다. 성공 15분, 실패 최소 2분 동안 새 외부 요청을 막는다. HTTP `Retry-After`가 더 길면 그 시각을 지킨다.
- `mode=archive`: 외부 호출 없이 보관된 공지만 날짜·검색·시장 조건으로 조회한다. 날짜는 KST 00:00부터 종료일 다음날 00:00 미만까지이다. 게시일 미제공 공지는 기간 검색에 포함하지 않는다.
- `mode=older`: 선택한 출처마다 공식 이전 페이지를 한 번씩 추가 수집한다. 첫 페이지 확인이 없으면 먼저 확인한다. 완료 후 목록은 첫 페이지로 돌아가 새로 보관한 자료도 빠짐없이 볼 수 있다. 예전 공지가 이미 모두 보관된 경우에는 이 버튼 없이 이전/다음 목록으로 조회한다.

공지는 공식 URL별로 중복 없이 누적하며 240건 제한이나 특정 시작일에 따른 삭제를 하지 않는다. 첫 수집본 `data/delistings.json`은 DB에 한 번만 보충한다. 배포의 `d1: DB`와 Drizzle 스키마·마이그레이션은 Sites 소스에 있다. `server/news-schema.sql`은 생성된 마이그레이션의 대응본이다. 런타임에서 테이블을 만들거나 스키마를 변경하지 않는다. 커서 방식 정렬은 게시시각과 공식 ID를 함께 사용해 같은 시각 공지를 건너뛰지 않는다.

성공·실패 상태, 이전 페이지 위치, 재요청 시각도 서버에 저장한다. DB 임대로 같은 출처·페이지의 동시 수집을 막고, 요청에 묶인 Promise를 요청 사이에 공유하지 않는다. 출처의 반복 페이지는 수집 제한으로 표시하며 전체 과거 수집 완료라고 하지 않는다. 파싱 실패·지역 제한도 보관 공지를 지우지 않는다. 날짜가 없는 공지나 실제 수집 범위는 출처별 상태에서 확인한다. 보관은 요청으로 확인한 공지부터 이루어지며 사이트가 닫힌 동안 자동으로 실행하는 예약 작업은 이 변경에 포함하지 않는다. 외부 목록이 공개하는 범위 밖이거나 삭제된 원문은 복원하지 않는다.

게시일은 종료일이 아니다. `effectiveAt`은 원문에서 확인한 일정에만 넣는다. 시간대가 명시되지 않은 페이지 날짜는 날짜만 표시하며, 연기·취소 공지는 일정 변경으로 분류한다. 현물·Alpha·USDC/주식 선물 공지를 임의의 USDT 무기한 차트로 연결하지 않는다.

## 백테스팅 패널

`dashboard.js`와 `dashboard.css`는 작업 영역의 공유 하단 패널을 제공하고 `news-ui.js`가 뉴스 UI를 담당한다. `dashboard-model.js`는 공식 링크 검증·검색·중복 처리·설정 검증을 맡는다. 기간(KST 날짜)·초기 자본·주문 비율·수수료·슬리피지 설정은 브라우저에 저장한다. 하단 패널은 열기/접기, 높이 조절, 최대화/복원, 리포트 탭을 지원하며 활성 분할의 종목·주기를 따른다. 전체화면 안에서도 사용할 수 있다. 2026-10-25부터 첨부 전략을 통합한 실제 데이터 기반 백테스팅을 실행한다. 계산·체결 가정과 이식 내역은 루트 `BACKTESTING.md`를 참조한다.

BingX 스캐너의 전체 종목 현재 펀딩율 조회는 명시적인 공개 `premiumIndex` 경로에 한해 symbol 없이 지원한다. 정산 이력·개별 캔들은 계약을 지정해야 한다.


## 작은 화면의 설명과 전체화면

`chart-info.js`가 위쪽 펀딩 설명과 아래쪽 데이터 범위 설명의 native details 열림 상태를 각각 저장한다. 처음에는 높이 820px 미만에서 접고, 큰 화면에서는 펼친다. 내용은 숨긴 동안에도 같은 DOM에서 갱신하며 다시 조회하거나 차트를 재생성하지 않는다. 설명 내용은 높이를 제한하고 내부에서 스크롤한다. 1화면과 4분할 모두 상단 모니터 아이콘으로 같은 작업 영역 전체화면을 사용한다. 개별 차트 최대화와 작업 영역 전체화면의 상태는 분리한다.

상장폐지 소식은 `tab-delistings` 패널 전체를 하나의 세로 스크롤로 사용한다. 공지 목록은 내용 높이를 유지하며 헤더·필터·보관 범위가 목록을 한 줄로 압축하지 않는다. 거래소·시장·기간 설정은 기본적으로 접힌 native details에서 펼치며, 접어도 적용 조건을 요약해 표시한다. 갱신 시 패널의 읽던 위치를 보존하고 검색·필터·페이지 변경 시 위로 돌아간다. 한 번에 30건을 표시하는 기존 페이지 수와 조회 주기는 유지한다.


## 그리기와 축 라벨

현재가·카운트다운 위에 마우스 가격이 겹쳐도 `chartCursorPrice`가 해당 패널의 native 가격 포매터로 표시한다. 포인터 라벨만 프레임당 한 번 갱신하고, 가격축·UI·그리기 캡처 중에는 숨긴다. 일반 포인터 이동 때문에 전체 그리기를 다시 만들지 않는다.

수직선과 크로스라인의 세로선은 보이는 모든 패널을 거쳐 실제 시간축까지 이어지며 한국시간 날짜 태그를 표시한다. 선을 하단 지표에서도 선택·이동할 수 있고, 수직선 이동은 시간 좌표만 바꾼다. 수평선·수평 레이·가격 노트 등은 해당 패널의 가격축 태그를 표시하며, 다른 도구를 선택하거나 그리는 중에는 기준점 가격·시간을 표시한다. 축 밖 좌표를 화면 끝에 가짜로 붙이지 않고, 겹치는 태그는 선택한 도구를 우선한다. 축 태그는 포인터 이벤트를 받지 않아 기존 축 확대·이동을 가로막지 않는다. 1화면·4분할 모두 같은 렌더러를 사용한다.

## 정산 주기 구간의 문맥

분봉 구간 안에 정산이 한 번도 없어도 주기를 계산할 수 있도록 `FundingHistory.partition`은 가격 구간 앞뒤의 정산 기록을 각각 두 건 보존한다. 조회 문맥은 최대 24시간 주기의 반복을 확인하도록 앞뒤 48시간을 요청한다. 이웃 기록은 주기 계산에만 쓰며 해당 가격 구간의 펀딩 신호·최저율에 넣지 않는다. 최근 정산 응답도 가격 구간 바깥의 기록을 버리지 않고 주기 계산에 사용한다. 현재 주기 추정에는 최신 기록 최대 아홉 건만 합쳐 포인터·실시간 갱신 비용을 제한한다.

선택한 거래소의 현재 주기 조회는 전체 캔들 수집과 별개로 시작하며 최대 분당 한 번으로 제한한다. 늦게 도착한 이전 코인의 응답은 무시한다. BingX처럼 현재 응답에 주기 필드가 없으면 연속 정산 기록으로 추정하며 공식 현재값으로 표시하지 않는다. MEXC 과거 정산의 `collectCycle`은 `intervalSource: official-history`와 함께 보존하고, 해당 정산에 대응하는 시간 범위에서만 우선 사용한다. 관측이나 백테스트가 붙인 `intervalHours`는 공식 근거로 승격하지 않는다. 자료 누락·API 보관 범위 밖의 구간은 현재 주기로 채우지 않는다. 일봉·주봉·월봉은 해당 봉에서 확인된 최소 주기를 표시한다.
