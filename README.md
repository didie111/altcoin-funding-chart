## 로컬 실행

저장소 루트에서 정적 HTTP 서버를 실행합니다. 예:

```sh
python -m http.server 8000
```

브라우저에서 http://localhost:8000/ 을 엽니다. BingX/MEXC 중계의 배포·출처 설정은 [server/README.md](server/README.md)를 참고하세요. 이 저장소에는 `server/server.js`나 npm 앱 서버가 없습니다.

## 검증

```sh
node --test tests/*.cjs tests/*.mjs
```

`tests/browser-responsive-backtest.html`은 생성 예제 138개로 노트북·PC·휴대폰의 고정 진행 표시와 단일 스크롤을 검사합니다. `tests/browser-backtest-backup.html`은 별도의 예제 IndexedDB로 저장소 이전·정밀 가격·즐겨찾기·결과의 백업 복원을 검사합니다. `tests/browser-backtest-restored-run.html`은 생성 예제 139개로 개별 실행·거래 보기·주기 변경 후 복원을 검사합니다. 예제 가격·성과는 일반 앱에서 사용하지 않습니다.

## 백업과 자료 보관

하단 **★ 일괄 결과 → 데이터 백업**은 즐겨찾기, 저장한 실행과 상세 결과, 현재 보관 중인 실제 1분봉·펀딩 원본을 한 `.dat` 파일에 담습니다. 원본이 없으면 저장 결과와 남은 시장자료를 백업합니다. **데이터 복원**에서 파일을 열면 즐겨찾기를 파일의 목록으로 바꾸고 그 목록과 맞는 저장 결과를 엽니다. 구형 파일에 즐겨찾기 목록이 없으면 기존 목록을 유지합니다.

**현재 설정으로 실행**과 개별 **실행**은 현재 브라우저에서 설정한 전략·기간·주기를 사용합니다. 같은 조건의 저장 결과는 그대로 엽니다. 설정이 달라지면 계산을 다시 하되, 요청 기간을 덮는 보관 원본이 있으면 거래소에서 다시 받지 않습니다. 저장 이후의 최신 구간도 필요하면 일괄 실행의 **저장 자료 우선**을 끄거나 개별 **최신 재계산**을 사용합니다. 보관 범위와 겹치면 빠진 최근 구간만 추가로 확인합니다.

요약만 있는 구형 결과도 바로 확인할 수 있습니다. 새 전략에는 실제 1분봉과 펀딩 정산 기록이 필요합니다. 임시 시장자료 캐시는 최대 32MiB, 압축 완료 상세 결과는 최대 64MiB입니다. 원본이 없는 구간은 공식 파일/API에서 확인합니다. 계산 시간은 봉 수·주기·기기에 따라 달라집니다.

소스 백업은 `backups/YYYY-MM-DD/NN-설명/`에 보관합니다. 코드 백업과 브라우저의 백테스트 자료 백업은 서로 다른 기능입니다.

## 원본으로 백테스트 연구

새 1분봉·전체 주기 실행에서 받은 원본은 검증 가능한 범위를 보관합니다. 원본이 없는 종목은 **★ 일괄 결과 → 원본 보관 → 원본 수집·이어서**로 결과를 다시 계산하지 않고 자료만 채울 수 있습니다. 보관된 구간은 건너뜁니다.

거래소 조회를 아예 막으려면 개별 **원본으로 실행** 또는 일괄 **보관 원본만 사용**을 선택합니다. 보관 결과의 전략으로 다시 실행하려는 경우에만 **저장 설정으로 일괄 실행** 또는 **이전 설정으로 이어서**를 선택합니다.
